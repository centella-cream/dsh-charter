`0.3.4` adds an opt-in model calibration layer to the review-only draft. It does not change the record
schema, standing prompt projection, or the model tool surface.

## Scope

- Adaptive-batched calibration core: local coverage ledger, bounded batches, capped concurrency, per-batch split retry, Host-side cross-batch merge, and partial/truncated/excluded diagnostics.
- Semantic aggregation and readable rewriting in the requested `zh`/`en` language.
- `c-*` calibration candidates with `mergedFrom` provenance and an additive `applyBootstrap` extension.
- Trusted Host-only evidence attachment for calibrated items; no evidence field is exposed on the wire.
- v9 contractness gate: drops heading/status/history/optional/pending material, reclassifies action items as deliverables, reserves the objective and deliverable quota, and filters model output; prompt v2.
- v10 review remediation: classified Remote business-error envelope and client error class, source-provenance objective/deliverable kinds, visible `conflicts`, strict-wire v8 batch diagnostics, degraded-part remapping, and run-level cache/retry documentation alignment.
- Objective completeness and deliverable coverage: source-objective fallback for shortened model objectives; planner selects all contract deliverables before invariants; model-omitted deliverables are restored from source and remaining omissions are visible as `model-omitted`.
- Plugin detail localization: `locale/{en,zh}.json` now declare `meta.detail` (`README.md` / `README.zh.md`); DSH 0.2.2-rc.5 does not infer a language from a lowercase README suffix.
- Capability/status method, consent gate, bounded in-memory cache and run id.

## Known limits

- Calibration is disabled by default. It requires `calibration.enabled: true` and a matching
  `calibration.consentVersion`; it sends compaction draft text to the configured model.
- The plugin detail page exports localized English/Chinese metadata whose description names the
  current `0.3.4` development candidate; the README is refreshed with current Pane and graph screenshots.
- No 0.4.0 readiness/execution-memory/relation capabilities are included.
- Local exact-artifact gates pass: package smoke, packed recovery, fresh DSH 0.2.2-rc.5 Web profile, and Gateway acceptance on DSH 0.2.1-rc.3/rc.4.
- Known limitation deferred to 0.3.5: a completed/no-pending Session summary (for example a finished release report) can still yield a historical objective and completion/evidence rows as draft candidates. This is an effect-quality limitation, not a 0.3.4 blocker under the release-owner decision.
- A/B protocol 1/2 are waived by the release owner as unsuitable for this opt-in draft-rewriting feature; no effect claim is made. en→zh draft calibration was manually accepted; zh→en manual acceptance is waived. Full L4 matrix, desktop formal hot-update acceptance and the release workflow remain. A real 10-turn Web test now passes with v8 defaults (3/3 batches, 24 candidates, no truncation); v7 default/tuned failures are retained as evidence in `docs/research/2026-11-24-calibration-ab/`. Adaptive batches, the v9 contractness gate, partial/truncated UI status and disclosure v2 are implemented; a second real-summary validation now preserves the objective and key deliverables; business errors and conflicts are visible; A/B and zh→en manual acceptance are waived; full L4 matrix, desktop formal hot-update acceptance and the release workflow remain.
- Review hardening restores language-follow fallback, gates calibration to zh/en, binds runs to source handles, wires mergedFrom excerpts into the review diff, validates explicit effort when adapter metadata is available, and covers actual 0.3.2/0.3.3 record fixtures plus calibration gate/cache/TTL/capability/failure tests. Cancellation relay and the per-ref suppressed selection set remain documented post-MVP items.
