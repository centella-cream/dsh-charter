# dsh-charter 0.1.0-rc.5

`0.1.0-rc.5` is the pre-stable product-correctness and release-hardening candidate. It does not add a 0.2
capability, domain, Remote method, persistent schema version, or information architecture.

## Added

- **Visible-only history review.** Bootstrap candidates start unselected. The Pane exposes a stable global
  40-row window, shows total/visible/selected counts, groups invariants and deliverables, and offers
  select/clear only for the rows currently shown. Fresh planning and text admission see only that visible window;
  unknown-outcome replay still sends the exact retained request.
- **Forward-schema read-only fence.** A finite integer `recordSchemaVersion` greater than the current version is
  classified as `invalid / future-schema / recoverable:false`. Prompt and tool reads fail closed; edit,
  initialize, restore, and stale-client restore attempts cannot overwrite it. Diagnostic export remains available
  as `schema-invalid`; the raw bytes are preserved.
- **Safe local-work discard.** Staged changes, the editor, and each composer have separate discard/clear
  actions. A full local-work discard is confirmed with a summary of what will be lost. Only explicit
  `abandonUnknown()` clears unknown-outcome replay evidence.
- **Committed/projected UI.** Revision, stored counts, and default active counts come from the committed view;
  staged results are labeled after Apply. A pure Apply-block reason is always shown next to the button and linked
  with `aria-describedby`. Empty-Charter calls to action remain available in every terminal bootstrap phase.
- **UTF-8 and failure handling.** Archive preview admission uses UTF-8 bytes, and missing or rejecting WebCrypto
  produces an explicit `cryptoUnavailable` result that keeps Restore disabled.
- **Error, ARIA, and touch improvements.** Connection failures carry a stable error kind; technical details are
  available in an expandable, escaped block; composers have distinct accessible names and invalid-state
  semantics; budget meters expose meter semantics; narrow/coarse-pointer controls have larger touch targets.
- **Real Gateway evidence.** `tests/gateway/authorization.spec.ts` drives the real `TypertGatewayService` on
  DSH `0.2.1-rc.3` and `rc.4`; owner/guest edit, guest maintenance and purge refusal, and pre-business denial pass.
- **Compatibility metadata and release evidence.** `engines.dsh`, peer ranges, and
  `dsh.compatibility.dshReleases` now contain the same seven verified DSH versions. A tracked compatibility
  runner and one-artifact release workflows are added for repeatable evidence.

## Verification

Use the current tree as the source of truth:

```bash
npm run check
npm run smoke:package
```

The checked-in compatibility runner records per-version evidence; the pack-once workflows are the release path.
Real Gateway authorization, browser recovery, Desktop ABI, and real-model compaction remain separate acceptance
gates and are not claimed by a plain `npm test` run.

## Compatibility

Supported DSH versions remain the seven declared versions: `0.1.7-rc.2`, `0.2.0-rc.1`, `0.2.0-rc.2`,
`0.2.1-rc.1`, `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4`. rc.4 records are readable without migration; a future
record schema is preserved read-only rather than restored.
