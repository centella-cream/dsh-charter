`0.2.2` adds a dependency-graph workspace view and closes the existing §6.5 dependency-conflict confirmation
gap. It is a client-focused patch: no record schema, migration, Host service, Remote wire, or prompt-projection
change.

## Added

- **Dependency graph in Workspace.** Local ego view with execution, candidate, and replacement-history lanes,
  synchronized with the always-present semantic list.
- **Bounded isolated fallback.** Contracts without dependency edges show a grid of at most 20 execution nodes and
  a short “add a prerequisite” hint; larger unlinked contracts hide the graph with an isolated-specific message.
- **Keyboard graph contract.** One Tab stop, arrow/`[`/`]` traversal, Enter for details, Escape to close and
  return toward the list, and a skip link to the semantic list.
- **Dependency-conflict confirmation.** A Change Set that adds or worsens a dependency conflict lists affected
  deliverables and requires a second Apply confirmation.
- **Compact prerequisite editing and windowing.** Each dependency row is a summary; its checkbox editor is opened
  on demand. The list renders 50 rows at a time with a “show more” path.

## Changed

- The dependency list no longer renders a native multi-select with up to 511 options per row.
- Graph and list edits produce byte-identical `deliverable.requires` Change Set ops; Apply remains the only
  commit point.
- Dense graph views degrade in order: hide replacement history, reduce depth, then hide the graph with a reason.

## Fixed

- Graph-to-list and graph-to-proposal focus paths expand the visible window before moving focus.
- Dependency summaries show local `D<n>` keys rather than internal item ids.
- Edge keys include the relation kind so matching requires/supersedes endpoints cannot collide.

## Upgrade notes

- Existing `0.2.1` records need no migration.
- The graph is a view over the existing relationship data; it is not a second source of truth.
- A dependency conflict still allows an explicit user override after the two-step confirmation; the graph never
  changes progress or lifecycle automatically.
