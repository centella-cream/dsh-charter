# dsh-charter 0.2.0

> **Status:** Released 2026-11-05 — npm and GitHub Release published.
> **Version scope:** `0.2.0`
> **Baseline:** 2026-11-05
> **Authority:** [version roadmap](../design/version-roadmap.md); [verification](../verification.md) for evidence.
> **Supersedes / Superseded by:** none / none.

`0.2.0` is the workspace, constraint-relationship, evidence, and release-process upgrade. It is published as
npm `dsh-charter@0.2.0` (`latest` and `next`) and GitHub Release `v0.2.0`. Functional boundaries are listed in
the workspace design.

## Status

- Package version: `0.2.0`.
- DSH compatibility: `0.2.2-rc.1` is declared and verified alongside the previous eight versions.
- Versioning rule: starting at `0.2.0`, releases use plain increments (`0.2.0`, `0.2.1`, ...) and never an
  `rc` suffix.
- Source acceptance: strict TypeScript, build/smoke, 36 files / 434 tests, and the nine-version DSH
  compatibility matrix pass on the current tree.
- Post-release diagnostics (real Desktop/browser checks, real-model compaction, performance) remain recorded in
  [verification](../verification.md); they do not change the immutable published bytes.

## Added

- Three primary areas: Workspace, Review Center, and Diagnostics & Maintenance.
- Deliverable `requires` dependencies with canonical graph validation, derived readiness states, stable
  `D<n>` prompt keys, and an editable prerequisite selector.
- Record schema v2 with in-memory v1 migration, proposal batches with typed provenance, and item
  `proposalBatchId` / `reviewedAtRevision` metadata.
- Objective proposals with initialize/redirect acceptance rules, required replacement reasons, reject,
  and purge tombstones.
- Proposal batch, objective proposal, item, and bounded recent-change query endpoints, plus `summary` and
  `watchSummary` Remote projections. The client store uses `watchSummary` plus paged queries; the Pane windows
  rendered rows, while the store still fetches all pages eagerly.
- Message proposal action that saves the latest real user message; pending `proposedRequires` resolved on
  acceptance; fork source refs; configurable proposal-batch limit.
- Canonical Change Set preview digest and `PREVIEW_MISMATCH` protection before Apply.
- Evidence Integrity and Fact Validity: evidence bindings, source projection integrity labels
  (`intact`/`missing`/`mismatch`/`unsupported`), user attestation, and owner-only registered validators
  (`workspace.path-exists`, `workspace.file-digest`, `workspace.file-contains`) with file-byte/total-byte/
  deadline bounds, cancellable reads, timeout/permission/unknown and stale-on-edit semantics. Validator
  metadata never enters standing prompt.
- Message proposal picker with text-range selection and invariant/deliverable kind.
- Bootstrap active-item dedupe, fork validity reset plus proposedRequires/evidence remap, independent objective-proposal
  pagination, and batch-candidate proposed prerequisites.
- Pending-only `charter_propose` agent tool; the model still cannot accept, reject, archive, restore, purge,
  edit, or change progress.
- Change Set before/after summary and digest in the edit result, plus a Host-canonical preview endpoint.
