# dsh-charter 0.2.1

> **Status:** Released 2026-11-06 — npm and GitHub Release published.
> **Version scope:** `0.2.1`
> **Baseline:** 2026-11-06
> **Authority:** [version roadmap](../design/version-roadmap.md); [verification](../verification.md) for evidence.
> **Supersedes / Superseded by:** `0.2.0` / none.

`0.2.1` is the post-`0.2.0` patch for the message-proposal form, diagnostics presentation, Pane typography, and
bounded recovery cache. It is published as npm `dsh-charter@0.2.1` (`latest` and `next`) and GitHub Release
`v0.2.1`.

## Status

- Package version: `0.2.1`.
- DSH compatibility: unchanged from `0.2.0`; all nine declared versions are matrix targets.
- Record schema: unchanged (`recordSchemaVersion: 2`); the new `dsh_charter_archives_v1` domain is a bounded,
  owner-only recovery derivative, not a second authority.
- Source acceptance: strict TypeScript, build/smoke, 36 files / 441 tests, and the nine-version compatibility
  matrix; candidate and promotion workflows passed.
- Local acceptance and real Web/Desktop ABI passed on 2026-11-06.
- Post-release: the compaction check still needs a post-compaction `charter_read` tool call, and the 512-item
  performance run remains separately recorded in [verification](../verification.md).

## Added

- Editable message proposals. Selecting a user message fills an editable body; the old character-range inputs are
  removed. Edited proposals use manual provenance and reject non-human actors.
- Owner-only recovery cache with `listArchives`/`readArchive` Remote methods. Snapshots are bounded to five per
  Session and 25 per profile, evicted oldest-first.
- Diagnostics form for fact validity with explicit target, method, path, and expectation fields; evidence
  integrity is a separate action and explanation.

## Changed

- Review and recovery forms share one field-label, helper-text, and card-description hierarchy.
- Pane header uses the lighter `dsh-context` title scale, compact metadata, and a flat divider instead of a hero
  card.
- Recovery lists cached snapshots directly; download is an independent export/audit operation. Local JSON import
  remains an advanced path.
- README/README.zh describe the current 0.2.1 capabilities and carry a current Pane screenshot.

## Fixed

- Message proposal and diagnostics state reset across Sessions.
- Proposal-batch source integrity survives the same-revision transition from an accepted Host view to the query
  view.
- Recovery cache survives Host restart; Session disposal no longer deletes it, and profile-wide LRU bounds stale
  entries.
- Restore labels distinguish cached recovery from imported files.

## Upgrade notes

- Existing `0.2.0` records are read without migration. The archive-cache domain is created lazily and is optional;
  if it cannot open, the primary record and ordinary editing remain available.
- `listArchives` and `readArchive` require the same owner-only maintenance capability as export/restore.
- Health records still refuse restore; cached snapshots are offered only for `absent-unconfirmed` or `invalid`
  targets.
